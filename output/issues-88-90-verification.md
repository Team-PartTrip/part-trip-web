# 추가 이슈 #88–#90 검증

## 구현 범위

- #88: 날짜 선택 위 기본 안내·시작일 선택 뒤 안내, 알려진 혼자/같이 여행 조건의 동행 선택지·초깃값, 당일치기 숙박 없음 고정·숙박 여행 제외, WALKING 질문 제거 및 이동 편의 답에서 생성 요청 도출. 서버에서 내려오지 않은 질문을 복원하지 않으며 나머지 서버 블록은 기존 추가 설정 영역에서 유지합니다. 새 여행은 이전 동행 설정을 재사용하지 않습니다.
- #89: 일정 장소 DTO description/typeLabel, 세부 종류와 설명(없으면 분류·주소), 비편집 카드의 네이티브 details 펼침. 사진·분류·평점·주소·설명·기존 편의 시설 조회·지도 링크를 제공합니다. 확정 일정의 화장실 안내는 접힌 카드에서도 유지합니다. 편집 중에는 상세 펼침 없이 기존 편집 기능을 유지합니다.
- #90: 일정·초대·그룹 화면에서 여러 명 여행이며 DONE/COMPLETED 이전인 경우 멤버 목록을 5초 간격 갱신. 멤버 조회 400/403/404는 재시도 지연 없이 안내 1회 후 목록으로 이동. 그룹장은 확정 뒤에도 내보내기와 초대를 사용할 수 있으며 DONE/COMPLETED는 숨깁니다.

## 검증 결과

- 단위·계약 테스트 104개 통과, 빌드·린트 통과.
- 신규 브라우저 회귀 검사: 여행 조건별 답·생성 요청, 같은 날짜 두 번 선택, 상세 누락값 대체·편집 차단, 멤버 참여·삭제 반영, 400/403/404별 안내·이동, DONE·혼자 여행의 갱신 중지. 실제 5초 간격을 사용합니다.
- 기존 #77–#87 브라우저 검사 26개 확인 항목 통과. 이 검사의 카카오 타일·주소 변환은 실제 외부 API를 사용합니다.
- 현재 서버 `https://api.dandi-trip.me/v3/api-docs`에서 Place.description/typeLabel과 멤버 GET·DELETE 경로를 확인했습니다. 과거 duckdns 호스트는 DNS 실패하여 검증 근거로 쓰지 않았습니다.
- Impeccable 기계 검사 결과 빈 목록. 데스크톱·375px 모바일 화면 캡처 및 가로 넘침 검사 수행.
