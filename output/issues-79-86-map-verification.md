# 실제 지도·현재 위치 주소 변환 후속 작업

상태: **운영 화면의 실제 카카오 지도·주소 변환 검증 통과** (2026-10-17 재검증). 이전 403 차단 후 두 이슈를 다시 열었고, 재검증 시 SDK가 정상 응답했습니다.

## 구현

- 카카오 지도 Web SDK를 직접 로드해 방문 장소·사진 좌표에 실제 Marker와 번호·이름 오버레이를 생성합니다.
- 모든 좌표를 포함하는 범위 맞춤, 목록/핀 선택 시 지도 이동, 모바일 크기 변경, 마커 정리를 처리합니다.
- 현재 위치 좌표를 카카오 Geocoder.coord2Address로 조회하고 도로명 주소를 우선하여 출발지 이름과 주소로 사용합니다.
- 주소 조회가 실패하면 좌표 문자열을 대신 저장하지 않습니다. 직접 지정 출발지가 미확정이면 생성을 차단합니다.
- 이전 주소 응답이 나중에 선택한 출발지를 덮어쓰지 않도록 취소 버전을 확인합니다.

## 확인된 검사

- 자동 테스트 100개, 빌드, 린트 통과.
- `tests/kakao-map-regressions.html` 통과: SDK 실패·재시도, 유효 좌표 마커·범위·선택·정리, 도로명 우선·경도/위도 순서, 주소 실패 시 생성 차단, 늦은 응답 무시.
- 위 브라우저 검사는 **SDK 모의 객체 검사**이며 실제 지도 타일·주소 API 성공 근거가 아닙니다.
- 기존 전체 브라우저 검사도 이제 실제 지도 핀과 로드된 타일이 없으면 통과하지 않도록 강화했습니다.

## 이전 실제 연결에서 확인된 차단 원인 (재검증 시 해소)

- 로컬의 유효한 단디 JavaScript 키: HTTP 403, `App(단디) disabled OPEN_MAP_AND_LOCAL service.`
- Vercel 운영 변수의 기존 키: 정상 JavaScript 키 형식이 아니며 HTTP 401 `wrong appKey format`.
- 기존 운영 변수를 로컬의 유효한 단디 JavaScript 키로 교체한 뒤 다시 내려받아 값 일치와 정상 형식을 확인했습니다. 교체 직후 운영 키의 실제 SDK 요청도 HTTP 403 `disabled OPEN_MAP_AND_LOCAL service`를 반환했습니다. 2026-10-17 재검증에서는 HTTP 200으로 바뀌었습니다.
- 현재 Chrome 계정의 개발자 콘솔은 회원가입·약관 동의 화면으로 연결되어 단디 앱 관리자 설정을 열 수 없습니다. 약관 동의나 새 개발자 계정 등록을 임의로 진행하지 않았습니다.

당시에는 서비스 활성화 후 실제 타일·핀 및 주소 API 성공 검증이 필요했습니다. 아래 재검증에서 해당 연결은 성공했습니다. 실제 계정의 서버 저장은 이번 검사 범위에 포함하지 않았습니다.

## 2026-10-17 실제 서비스 재검증

- 운영 도메인과 localhost의 실제 SDK 요청 모두 HTTP 200. 이전 403의 설정 변경 시점·주체는 확인하지 않았습니다.
- `https://dandi-trip.me`에 배포된 실제 코드를 별도 브라우저에서 실행했습니다. 앱 백엔드 응답·쓰기는 가로채고 카카오 SDK·타일·주소 API는 가로채지 않았습니다.
- 실제 카카오 타일 이미지 로드 및 방문 장소·사진 좌표의 핀 생성 확인. 시안 이미지 없음. 화면 증거: `output/playwright/issues-79-live-map.png`.
- 위치 권한을 허용한 브라우저에 공개 좌표 `(35.79, 129.33)`를 입력했습니다. 실제 카카오 주소 변환 결과는 `경상북도 경주시 불국로 385`입니다.
- ‘지금 있는 곳’ 선택 후 이 주소가 UI에 표시되고 일정 생성 요청의 `departurePoint.placeName`에 포함되며 원래 위도·경도가 유지되는 것을 확인했습니다.
- 전체 브라우저 회귀 검사 26개 확인 항목 통과. 실제 계정 일정 생성·메타데이터 저장·서버 재조회는 수행하지 않았습니다.

프론트엔드 이슈의 지도 표시·주소 변환·생성 요청 전달 동작은 검증됐습니다. 기존 403 차단 설명은 이전 관측 기록이며 현재 상태가 아닙니다.
